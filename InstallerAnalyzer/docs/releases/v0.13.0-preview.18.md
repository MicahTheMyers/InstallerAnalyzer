# v0.13.0-preview.18 — LPile testing fixes

- Normalize quoted Windows uninstall InstallLocation directories before discovery; ignore malformed locations instead of aborting the analysis.
- Keep QSetup removal hidden even when a vendor's registered quiet command contains only /silent. Preserve other vendor operation arguments.
- Check that a visible-style installer window actually intersects a monitor before classifying it as on-screen UI. LPile creates off-screen owner/progress windows; the detector previously rejected these and stopped working unattended commands. The main-window fallback uses the same check. Actual on-screen windows still cause rejection.

Validation: 659 application/WPF checks; 19 Windows PowerShell path checks; 6 QSetup command checks; 6 real native-window presentation checks; all 11 generated script families parse in Windows PowerShell. Diagnostic install/removal probes use the production process monitor and verified exit code 0 with no presented UI. LPile's raw window bounds were outside every monitor.

The public release is unchanged. License activation and engineering calculations are outside installation lifecycle validation.

Real app acceptance: LPile 2022 (12.12), SHA-256 A6B9E915717C9DEDEBABC6652EDB26F1A4E4C1EEFF92C818A10E6187783E6538, completed initial manual installation, silent removal, silent reinstall and final silent removal in a fresh app-managed Windows Sandbox. Both silent replay exit codes were 0, no presented installer UI was detected, final application absence was verified, and the app automatically recorded one successful catalog validation. The saved Cloud Subscription profile was used without account sign-in or activation. The guest used the saved .NET 3.5 preparation and legacy compatibility settings; this run does not establish that LPile requires .NET 3.5 or validate activation, reboot behavior, fresh-machine unattended prerequisite installation, or a live Datto deployment.
