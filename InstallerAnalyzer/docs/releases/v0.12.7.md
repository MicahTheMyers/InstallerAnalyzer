# v0.12.7 — local catalog, discovery fixes, custom colors

Built from the supplied v0.12.6 source archive. ImmyBot integration testing is excluded from this work.

## Changes

- Local SQLite catalog remembers successful original-package lifecycles by SHA-256. It stores installed identity, arguments, detection key, uninstall command, and validation counts. A hit supplies a preferred candidate; it never bypasses fresh Sandbox validation.
- Catalog viewer is available in Settings. Failed, interactive, incomplete, response-file-dependent, and extracted-child-only strategies are not memorized as original-package successes.
- Stable lifecycle identifiers prevent repeated checkpoint/dashboard reads from inflating validation counts.
- Recognize installer markers stored as UTF-16LE, including unaligned embedded payloads.
- Require successful installer exit codes. Preserve the successful discovery strategy through reinstall and copy its validated arguments back into the Analyze page.
- Distinguish launched application windows from installer UI using the registered installation directory and actual process path. Registration alone no longer fabricates a successful exit code or terminates a running installer transaction.
- Add bounded install-operation hypotheses and improve uninstall candidate generation. Preserve operation/product parameters, avoid plain interactive uninstall commands, support initial uninstall discovery, and record the final proven uninstall command.
- Chromium-family uninstall arguments are inferred from observed command semantics. Reference: [Chromium administration documentation](https://www.chromium.org/administrators/common-problems-and-solutions/).
- Stop exploration when a rejected candidate leaves a changed installation baseline. Prerequisite-only registrations cannot prove installation of the primary application.
- Silent Only refuses to start an interactive response-file recorder.
- Stop Tests and Stop Sandbox are red, including their hover styles, in every theme except Hacker, which retains green.
- Separate owned RGB dialogs edit the custom theme color and custom accent color. Each has three colored 0–255 sliders, a preview, hexadecimal value, Apply and Cancel. Colors persist across restarts.
- Modern Sandbox client windows are included in unattended minimization.
- Analyze runs static scans outside the UI thread, ignores stale selection results, fits the initial window to the desktop, and scrolls on smaller screens. Evidence text wraps.
- Cancellation preserves partial analysis, marks waiting items stopped, restores controls, and releases the cancellation token. Sandbox teardown runs outside the UI thread while preserving its existing sequencing.

## What to test

1. Run a full silent lifecycle, open Settings → View local catalog, then select the identical package again. The evidence should show an exact hash match. Renaming a different binary to that filename must not produce a hit.
2. Run Advanced IP Scanner silently. Its launched application window should not be classified as installer UI; the installer must still exit successfully.
3. Check Chrome-family uninstall discovery, unknown bootstrapper install-operation hypotheses, and failures requiring prerequisites or licensing input.
4. Stop a test during Sandbox startup and during installation. The queue must stop, partial diagnostics must remain, and TestInstallers must be preserved.
5. Inspect both stop buttons in Dark, Super Dark, Light, Purple, Custom and Hacker. Test hover and disabled states.
6. Apply and cancel RGB colors, restart the app, and check that the saved theme/accent returns. Hacker must retain its green stop controls.
7. Resize the app and check Analyze and Sandbox scrolling, History, Settings, and read-only catalog viewing.

See the accompanying test report for actual executed results and remaining failures. Historical handoff claims are not imported into the catalog as proof.

## Additional reliability corrections validated during USB testing

- Preserve actual vendor uninstall exit codes; normalize Chromium setup's documented successful uninstall statuses only when the observed executable path and uninstall operation match that family.
- Recognize native Appx/MSIX registrations from EXE bootstrappers and remove the exact registered package without EXE argument guessing.
- Detect missing-DLL loader failures as prerequisite failures, rather than claiming no silent switch exists.
- Discover embedded MSI instance transforms from the package's read-only storage table. Test bounded quiet instance-install candidates and keep only a full lifecycle success.
- Refresh registered application directories after reinstall. OneDrive may change its version directory between the initial install and clean reinstall.
- A reused startup PID cannot hide a later installer window. Installed-application exclusions require the registered installation/uninstall directory and a matching process executable path.
- Detect a modern Sandbox environment that has died even if its client remains open on an error screen. Preserve diagnostics and report the interruption promptly.
- Normal Sandbox startup, copying, and user-requested shutdown now run outside the UI thread. Stop during startup is honored, overlapping runs are blocked, and stopping promotes the partial checkpoint into a diagnostic result.
- Center the initial window inside the current work area so title-bar buttons remain reachable on this display.
- Refresh catalog product metadata from each new successful proof, including online bootstrapper version changes.
- Correct overlapping Test Mode heading and test-type controls; the status badge now remains visible.
- Keep the Test Mode selected count synchronized with individual checkboxes, prevent queue refresh during a run, and wrap result text instead of requiring horizontal scrolling.
