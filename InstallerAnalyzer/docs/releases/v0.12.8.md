# v0.12.8 — optional read-only AI Assist

AI Assist explains a selected Test Mode result or live diagnostic snapshot in a chat panel. It supplies advice only. It has no command runner, installer controls, arbitrary file access, registry access or catalog editor. Model replies are displayed as plain text; requested tool actions are rejected.

## Settings and layout

- Off by default for both new and existing settings files that lack this option.
- The option appears directly under Enable Test Mode, and is hidden while Test Mode is disabled.
- Turning Test Mode off also turns AI Assist off, cancels any pending request, and clears the in-memory chat.
- Enable the option to expose its connection settings and expand the chat area. It appears with Settings and Test Mode, and collapses on other pages.
- Wider displays use a side panel; narrower displays dock chat below the workspace. The window expands within the work area where space permits. Test Mode scrolls to keep controls reachable. Collapsing restores the original window dimensions.
- Choose a diagnostic test in the chat, use Preview diagnostics to see the snapshot, then press Explain or type a question and Send. Ctrl+Enter also sends. Cancel only cancels the AI request; installer tests continue independently.
- Choosing another test/provider clears the conversation and cancels its pending response. New results supersede the selected live snapshot, preventing an old response being shown for a new result.

## Provider setup

**OpenAI:** Choose OpenAI and enter a model ID that your API account can use. Enter your API key in the password field and Save key, or set `INSTALLERANALYZER_OPENAI_API_KEY` before starting the app. The environment key takes precedence. Saved keys use Windows DPAPI for the current Windows user and are not included in settings JSON, diagnostics or chat prompts. Remove saved key deletes the app's protected copy; it does not remove environment variables. API usage is billed separately from a ChatGPT subscription. No key is bundled and no model is chosen automatically.

**Local Ollama:** Run an existing Ollama server on this computer, choose Local Ollama, enter an already installed model name, and set its base address, normally `http://127.0.0.1:11434`. IPv4/IPv6 loopback and localhost are supported. Remote addresses, embedded URL credentials, URL paths/queries and explicit cloud model names are rejected. The app neither installs Ollama nor downloads models. Its local HTTP client bypasses proxies; the server's own configuration controls any further routing. The OpenAI credential is never attached to local requests.

Both connections use bounded text-only requests without function tools. Requests have a three-minute timeout and may be cancelled. Responses and conversation history are bounded; conversations are kept in memory and are not automatically saved.

## Diagnostic scope and privacy

Nothing is sent merely by enabling AI Assist, running a test, receiving a result, or opening Preview. Only Send/Explain contacts the configured provider.

The collector reads fixed filenames from the selected test's diagnostic folder: allow-listed fields in `regression-result.json`, `install-analysis.json`, and its checkpoint, plus bounded recent error/event excerpts from `analysis-debug.jsonl` and `msi-install.log`. It excludes arbitrary files, installer binaries, scripts, settings, credential files and the catalog. It refuses linked diagnostic files/folders, limits JSON size, and bounds UTF-8/UTF-16 log tails and final snapshot length.

Common password/token/API-key/license-key values, bearer credentials, profile usernames and email addresses are redacted before display/transmission. Redaction cannot identify every possible secret; review the preview before sending. Questions and recent conversation turns are also redacted. OpenAI receives the snapshot, question and recent turns when requested. Its response-storage flag is disabled; this is not a promise of zero provider retention.

Diagnostic content is explicitly described to the model as untrusted evidence rather than instructions. The assistant is prompted to distinguish observed facts, likely causes and missing information. Its explanation does not turn a failed/partial test into a catalog success, and none of its suggestions are applied automatically.

API references: [OpenAI Responses API](https://developers.openai.com/api/reference/python/resources/responses/methods/create), [Ollama chat API](https://docs.ollama.com/api/chat).

## Validation status

Release compilation and self-contained Windows x64 publishing succeed with zero warnings/errors. Source/XML checks verify the settings placement, disabled defaults, panel structure, request gates, no-tools payloads, cancellation guards and unchanged existing Sandbox/catalog/script engines.

The regression harness includes AI-specific checks for UI gating, collapse/restore, cancellation, diagnostic allow-lists and redaction, unchanged source files, local endpoint restrictions, both provider payload/response formats, missing configuration, authentication errors, unsupported actions and oversized responses. These use a fake HTTP handler and do not need a real key or model.

**Those executable checks have not run:** Windows Application Control blocked the new Regression.dll under the computer's Enterprise signing-level policy. No bypass was attempted. The final application's visual smoke test, actual persistence/DPAPI operations and live OpenAI/Ollama requests remain unverified. The previous v0.12.7 installer lifecycle results remain historical evidence, not a fresh v0.12.8 regression run.

After normal signing approval, build the included Regression project and run `--ai-verify` and `--verify`, then check both providers and the responsive layout. Verify that disabling Test Mode hides AI Assist and cancels an active reply, that no requests occur while disabled, and that an installer test continues independently of chat cancellation.
