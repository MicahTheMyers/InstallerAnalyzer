## 24 — Datto RMM deployment support

Status: initial implementation and local acceptance complete (2026-11-02). 606 .NET/WPF + 184 PowerShell checks and 11 syntax checks pass; 18 fresh Sandbox checks include two real install/remove cycles as LocalSystem. Datto tenant acceptance remains pending the user office test. Export is a ZIP creation kit, not native CPT. See ../DATTO-RMM-OFFICE-TEST.md.

Add Datto RMM as a deployment target alongside ImmyBot, using the same measured installer identity, validated strategies and lifecycle evidence.

Initial scope:

- Generate Datto RMM-oriented PowerShell installation, detection and uninstall output from validated strategies. Research the official component and import requirements before selecting the export format.
- Export the required installer/response files and supporting scripts with predictable paths and clear upload instructions.
- Handle execution context, architecture, working directory, parameters, logging, exit codes and reboot outcomes according to Datto RMM's documented behavior. Preserve unknown or unsupported cases explicitly.
- Provide a Datto RMM preview/export workflow without treating generated output as validated merely because it was exported. Preserve the existing ImmyBot workflow.
- Keep credentials and secrets out of generated scripts and exports. Direct tenant/API integration and remote job submission are separate future scope, not prerequisites for the initial export workflow.

Acceptance:

1. Review the current official Datto RMM documentation and define the supported component/deployment contract.
2. Verify generated commands, file layout, quoting, parameters and exit/reboot handling with focused fixtures.
3. Validate install, detection, uninstall and final absence in a disposable Windows test environment with representative installer families.
4. Verify the exported component through a real Datto RMM job on a disposable test device when tenant access is available. Sandbox success alone does not establish Datto RMM execution success.
